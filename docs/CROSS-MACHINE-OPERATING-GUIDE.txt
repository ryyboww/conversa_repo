CONVERA STRATEGIES
CROSS-MACHINE OPERATING GUIDE
Mac + Windows

Purpose
=======
Use GitHub as the shared handoff point between the Mac and Windows machines.
Each machine works on its own short-lived branch. The shared branch,
main_conversa, is kept stable and integration-ready.

Repository
==========
GitHub remote:
https://github.com/ryyboww/conversa_repo

Shared branch:
main_conversa

The repository folder is the folder containing package.json, src, public,
and .git.

ONE-TIME SETUP ON EACH MACHINE
===============================
1. Install Git.
2. Install Node.js using the version requested by .nvmrc or .node-version.
3. Clone the repository into a new folder. Do not clone inside another copy.

Mac Terminal:
  git clone https://github.com/ryyboww/conversa_repo.git
  cd conversa_repo

Windows PowerShell:
  git clone https://github.com/ryyboww/conversa_repo.git
  cd conversa_repo

4. Install project dependencies:
  npm install

5. Confirm the project works:
  npm run check
  npm run build

Do not copy node_modules, dist, or .astro from the other machine.

START EVERY WORK SESSION
=========================
From the repository folder:

  git status --short --branch
  git switch main_conversa
  git pull --ff-only

If the status command shows changes, stop and inspect them before pulling.
Do not pull over uncommitted work.

Create a task branch before editing:

Mac:
  git switch -c mac/short-task-name

Windows:
  git switch -c windows/short-task-name

Use lowercase words separated by hyphens. Examples:
  mac/update-contact-page
  windows/fix-mobile-header

If the task branch already exists locally, use this instead:
  git switch branch-name
  git pull --ff-only

NORMAL WORK CYCLE
=================
1. Make one small, coherent change.
2. Review the files changed:

  git status --short
  git diff --check
  git diff

3. Test site changes:

  npm run check
  npm run build

4. Commit only the intended files:

  git add path/to/file1 path/to/file2
  git commit -m "Describe the change"

5. Push the task branch:

Mac example:
  git push -u origin mac/update-contact-page

Windows example:
  git push -u origin windows/fix-mobile-header

6. Open a pull request on GitHub from the task branch into main_conversa.
7. Wait for checks to pass and merge the pull request.
8. On the other machine, update main_conversa before starting new work.

HANDOFF CHECKLIST
=================
Before handing work to the other machine:

  git status --short --branch
  npm run check
  npm run build
  git add <only intended files>
  git commit -m "Describe the completed change"
  git push -u origin <your-task-branch>

Then tell the other operator:
- the task branch name;
- what changed;
- what was tested;
- anything intentionally left for follow-up.

The other machine should not continue editing the same task branch. It should
wait for the pull request to merge, then start from updated main_conversa.

FILES THAT MUST STAY LOCAL
==========================
Never commit or copy these between machines:
- node_modules/
- dist/
- .astro/
- .env or any .env.* file containing local values
- activation reports or local audit output
- editor caches
- passwords, API keys, tokens, or private certificates

The checked-in .vscode/mcp.json is shared project configuration. Do not replace
it with a Mac-only or Windows-only version. Keep machine-specific MCP settings
outside the repository.

SAFE RECOVERY COMMANDS
======================
If you changed files but are not ready to commit:

  git stash push -u -m " WIP: describe task "
  git switch main_conversa
  git pull --ff-only

Later restore the work:

  git switch <your-task-branch>
  git stash list
  git stash pop

If a pull says local changes would be overwritten, stop. Do not use reset --hard.
First inspect:

  git status --short
  git diff

If branches seem to diverge:

  git fetch origin
  git log --oneline --decorate --graph --left-right HEAD...origin/main_conversa

Ask for review before resolving conflicts in production content, deployment
files, package files, or shared configuration.

DO NOT DO THESE THINGS
======================
- Do not force-push main_conversa.
- Do not use git reset --hard to solve a pull problem.
- Do not edit directly on main_conversa.
- Do not have both machines work on the same task branch at once.
- Do not commit generated output or secrets.
- Do not run npm install in an old nested copy of the repository.

DAILY QUICK CHECKLIST
=====================
[ ] Open the correct repository folder.
[ ] Check status.
[ ] Update main_conversa with git pull --ff-only.
[ ] Create a Mac or Windows task branch.
[ ] Make one focused change.
[ ] Run npm run check and npm run build for site changes.
[ ] Commit and push the task branch.
[ ] Use a pull request to merge into main_conversa.
[ ] Update the other machine only after the merge.
